# Phase 5.4 — Localization implementation plan

Spec: `docs/superpowers/specs/2026-09-26-localization-strategy.md` (approved). Roadmap: Phase 5.4 in
`ROADMAP.md`. Languages: `en` (source, default, fallback), `es`, `fr`, `ca`.

## Decisions taken while planning

- **Catalog files** live in `packages/i18n/arb/{en,es,fr,ca}.arb`. Each file carries `@@locale`, so
  `gen-l10n` does not depend on the filename. `en.arb` is the only file with `@key` metadata.
- **`packages/i18n` is an npm workspace** with one plain Node script, `scripts/build.mjs`. It checks the
  catalogs (same keys as `en`, same placeholders, ICU parses) and writes `dist/<locale>.json` (metadata
  stripped) plus `dist/index.d.ts` (a `MessageId` union). It runs from the root `prepare` script,
  like `api-types`, so a fresh `npm ci` builds it before web typecheck/test. The check is exported and
  covered by a `node --test` file.
- **Mobile reads the shared ARB files directly** (`arb-dir: ../../packages/i18n/arb`). Verified with
  Flutter 3.47.5 before relying on it; the sync-script fallback in the spec is not needed. The generated
  `AppLocalizations` goes to `lib/l10n/gen/`, is regenerated by `flutter pub get` (`generate: true`) and
  is git-ignored.
- **Natural case in the catalog**, uppercase in styling (spec, "Uppercase styling"): CSS `uppercase` on
  web, `.toUpperCase()` in Dart, only where the UI is uppercase today. Tokens that look like identifiers
  (`PUZZLE_CLEARED`) stay as written.
- **Not in the catalog:** the `SUDOKU 2077` wordmark, the build tag, grid digits, API wire values, and
  the four language names (always shown in their own language, a 4-entry constant on each client).
- **English is bundled** on web as the default messages and fallback; `es`/`fr`/`ca` are lazy-loaded
  with dynamic `import()`. Tests render inside the `en` provider.
- **Error codes:** `ErrorResponseSchema` gains a required `code` (`ErrorCodeSchema` enum). Additive for
  consumers, so not a breaking change. The API's catch-all error handler maps by status (401, 404, 429,
  other 4xx, 5xx), and a not-found handler makes unknown routes use the same shape. Clients map the
  codes they show to catalog keys and fall back to a generic message.
- **Mobile language state:** a `LocaleController` (`ChangeNotifier`) over `shared_preferences`
  (`locale`, `languageChosen`). The first-launch screen applies the tapped language live, so the
  confirm button already reads in that language; confirming sets `languageChosen`. The OPTIONS screen
  reuses the same language list.

## Tasks (one commit each, Conventional Commits)

As landed, the translations (task 10) went in before the language pickers (tasks 6 and 8), so the
pickers could ship all four languages at once.

1. `docs(repo)`: this plan; add the `i18n` scope to `AGENTS.md`.
2. `feat(i18n)`: `packages/i18n` with `en.arb` (all current copy from both clients), build/check script
   and its test, `prepare` hook.
3. `feat(types)`: `ErrorCodeSchema` + `code` on `ErrorResponseSchema`.
4. `feat(api)`: send `code` from every error path; tests.
5. `feat(web)`: `react-intl` provider fed by a new `locale` setting, `<html lang>` sync, lazy locale
   JSON, all copy through the catalog, locale-aware date on the profile page, API error codes
   translated, `formatjs/no-literal-string` lint rule, tests wrapped in the `en` provider.
6. `feat(web)`: LANGUAGE row in a shared settings panel, and a SETTINGS entry on the title menu that
   opens it.
7. `feat(mobile)`: `flutter_localizations` + `intl` + `l10n.yaml`, all copy through `AppLocalizations`,
   difficulty labels from the catalog (`wireName` stays wire-only), tests pump the delegates.
8. `feat(mobile)`: `shared_preferences`, `LocaleController`, first-launch language screen, OPTIONS
   entry and screen. Design mock-up added to the Polish Lab artifact first.
9. `ci(mobile)`: run `mobile.yml` on `packages/i18n/**`; add `flutter build apk --debug` now that a
   native plugin exists. `ci.yml` already runs the i18n check via `npm run test`.
10. `feat(i18n)`: `es`, `fr`, `ca` translations (French uses U+202F before `: ; ! ?`), iOS
    `CFBundleLocalizations`, Android `locales_config.xml`.
11. `docs(repo)`: tick Phase 5.4 in `ROADMAP.md`.

## Verification

- Root: `npm run typecheck`, `npm run lint`, `npm run test` (API tests need `docker compose up -d`).
- Mobile: `dart format .`, `flutter analyze`, `flutter test`, `flutter build apk --debug`.
- Manual: web in each language (title, settings, board, dialogs); mobile first launch → pick a
  language → title; OPTIONS → change language; restart keeps the choice.
- Length pass: HUD, tier cards and number-pad action row in `fr`/`ca` at 360 px width.

## Out of scope

RTL and non-Latin scripts; server-side settings sync (Phase 3 web / Phase 6 mobile); a TMS.
